prompt_raw=Задача: реализовать истинный 2д-трансформер с 2д-вниманием для Orbit Wars.

Главная схема:

64×2 -> 64×64 -> 64×64 -> ... -> 64×64 -> 64×2

Вход фиксирован:

- форма входа: 64×2
- строка = слот планеты
- порядок строк = существующий порядок кодировщика, основанный на евклидовом расстоянии
- столбец 0 = класс владельца: своя / враг / нейтральная / пустая
- столбец 1 = сжатое число кораблей

Программа должна делать только две внешние вещи:

1. сформировать вход 64×2
2. разобрать выход 64×2 в игровые команды

Запрещено добавлять в код ручные признаки пар:

- расстояние
- угол
- время полёта
- пересечение солнца
- ручная оценка пары источник-цель
- любые эвристики откуда-куда

Всё между входом и выходом должно быть обучаемым.

Обязательная внутренняя цепочка модели:

1. принять 64×2
2. обучаемо развернуть в 64×64
3. прогнать через N внутренних 2д-слоёв формы 64×64
4. каждый 2д-слой должен обрабатывать всю таблицу 64×64 как единый объект
5. внимание должно быть истинно двумерным: не обычное внимание по 64 строкам, а работа по таблице отношений 64×64
6. свернуть 64×64 обратно в 64×2

Смысл 64×64 нельзя задавать руками. Модель сама должна научиться, что хранить в этой матрице: связи, угрозы, приоритеты, скрытые признаки, варианты отправки.

Выход фиксирован:

- форма выхода: 64×2
- строка выхода = строка источника
- столбец 0 = выбор цели в формате, совместимом с текущим декодером
- столбец 1 = доля кораблей для отправки

В чем суть вихода - прога парсит откуда-куда и сколько, потом считает как сделать так чтоб эта отправка в цель попала с учетом орбит, скорости кораблика и прочего 

Критерий успеха:

- в коде реально существует внутреннее обучаемое представление 64×64
- несколько промежуточных слоёв сохраняют форму 64×64
- приложение не подмешивает ручную стратегию
- приложение только кодирует вход и декодирует выход
- текущий внешний интерфейс агента остаётся совместимым
